# 完整单元配对逻辑优化说明

**日期**: 2026-03-24  
**版本**: v0.4.1  
**优化内容**: 修正完整单元数量验证逻辑

---

## 📌 问题背景

### 原有逻辑（错误）

之前测试清单中假设：
```
完整单元数 = 题目总数 Q
```

### 实际情况（正确）

完整单元数 **不一定等于** 题目总数 Q，因为可能存在：

1. **有题目无答案** - 题目纸存在，但答题纸缺失或该题未作答
2. **有答案无题目** - 答题纸存在，但题目纸缺失或识别失败

系统的正确行为应该是：
- **尽量组合所有能配对的题目 + 答案**
- 允许存在只有题目或只有答案的单元
- 不强制要求完整单元数等于题目总数

## ✅ 优化内容

### 1. 重新定义关键指标

#### 新指标定义

| 指标 | 定义 | 计算方式 |
|------|------|----------|
| **Q** | 识别出的题目总数 | 步骤 4 统计 |
| **Q_has_answer** | 有答案的题目数量 | 步骤 4 中既有 `question_slice_path` 又有 `answer_slice_path` 的题号数 |
| **A_has_question** | 有题目的答案数量 | 步骤 4.5 中既有 `answer_slice_path` 又能关联到题目的数量 |
| **M** | 理论最大配对数 | `M = max(Q_has_answer, A_has_question)` |

#### 逻辑关系

```
Q_has_answer ≤ Q  （有答案的题目数 ≤ 总题目数）
A_has_question ≤ Q_has_answer（有题目的答案数 ≤ 有答案的题目数，通常相等）
M = max(Q_has_answer, A_has_question)（理论应该配对的最大数量）
完整单元数 ≥ M - 容错数（允许少量配对失败）
```

#### 修改位置 4: 关键指标（12.2 节）

**新增指标**:
```markdown
| **配对完整率** | **≥95%** | **___%** | ☐ | 有题有答案的都配对 |

**配对完整率计算**:
- 公式：`配对完整率 = min(完整单元数，M) / M × 100%`
- 其中 M = max(Q_has_answer, A_has_question)
- 目标：≥95%（允许少量配对失败）
```

## 🔍 验证逻辑示例

### 场景 1: 完整试卷（理想情况）

```
输入：题目纸 3 张 + 答题纸 1 张
识别结果:
- Q = 21（21 道题）
- Q_has_answer = 21（所有题都有答案）
- A_has_question = 21（所有答案都有题目）
- M = max(21, 21) = 21

预期:
- 完整单元数 ≥ 21 - 2 = 19
- 配对完整率 = min(完整单元数，21) / 21 × 100% ≥ 95%
```

### 场景 2: 答题纸缺失（有题无答案）

```
输入：题目纸 3 张，答题纸缺失
识别结果:
- Q = 21（21 道题）
- Q_has_answer = 0（没有答案）
- A_has_question = 0（没有答案）
- M = max(0, 0) = 0

预期:
- 完整单元数 = 0（无法配对）
- 配对完整率 = N/A（无配对）
- 但题目切片仍然存在（21 个题目切片）
```

### 场景 3: 题目纸缺失（有答案无题）

```
输入：答题纸 1 张，题目纸缺失
识别结果:
- Q = 0（没有识别到题目）
- Q_has_answer = 0（没有题目）
- A_has_question = 21（21 个答案，但无法关联题目）
- M = max(0, 21) = 21

预期:
- 完整单元数 = 0（无法配对，因为没有题目）
- 但答案切片仍然存在（21 个答案切片）
- 系统应标注"答案无对应题目"
```

### 场景 4: 部分缺失（实际情况）

```
输入：题目纸 2 张（缺 1 张）+ 答题纸 1 张（完整）
识别结果:
- Q = 14（识别到 14 道题，缺 7 道）
- Q_has_answer = 14（14 道题有答案）
- A_has_question = 14（14 个答案有关联题目）
- M = max(14, 14) = 14

预期:
- 完整单元数 ≥ 14 - 2 = 12
- 配对完整率 = min(完整单元数，14) / 14 × 100% ≥ 95%
- 系统应标注缺失的 7 道题"有答案无题目"
```

## 📊 数据流向图

```
步骤 4: 内容提取
├── 识别题目 → Q 个题目
└── 统计 Q_has_answer → 有 answer_slice_path 的题号数

步骤 4.5: 答案切片
├── 识别答案 → 答案切片
└── 统计 A_has_question → 能关联到题目的答案数

步骤 5: 合并结果
├── 题目 + 答案配对
└── 生成 linked_results

步骤 6: 涂卡识别
├── 生成完整单元
├── 完整单元数 = len(complete_units)
└── 验证：完整单元数 ≥ M - 2
```

## 🎯 测试验证要点

### 验证 1: 统计准确性

- [ ] 步骤 4 正确统计 Q_has_answer
- [ ] 步骤 4.5 正确统计 A_has_question
- [ ] M = max(Q_has_answer, A_has_question) 计算正确

### 验证 2: 配对完整性

- [ ] 所有 Q_has_answer 的题目都出现在 complete_units 中
- [ ] 不存在重复配对（每个题号只出现一次）
- [ ] 配对完整率 ≥ 95%

### 验证 3: 缺失处理

- [ ] 题目缺失时，answer_image_path 为空或标注缺失
- [ ] 答案缺失时，question_image_path 为空或标注缺失
- [ ] combined_image_path 至少包含一个（题目或答案）

### 验证 4: 边界情况

- [ ] Q_has_answer = 0 时，完整单元数 = 0
- [ ] A_has_question = 0 时，完整单元数 = 0
- [ ] Q_has_answer ≠ A_has_question 时，正确处理

## 📝 未来开发建议

### 1. 增强缺失标注

在 `complete_units.json` 中添加缺失标注字段：

```json
{
  "question_number": "15",
  "question_image_path": null,  // 题目缺失
  "answer_image_path": "answer_slices/.../A015.jpg",
  "combined_image_path": "complete_unit_images/.../combined_Q015.jpg",
  "missing_info": {
    "question_missing": true,
    "answer_missing": false,
    "reason": "题目纸缺失"
  }
}
```

### 2. 生成缺失报告

在步骤 6 生成缺失报告：

```json
{
  "missing_questions": [
    {"number": "15", "reason": "题目纸缺失"},
    {"number": "16", "reason": "答题纸缺失"}
  ],
  "summary": {
    "total_questions": 21,
    "complete_units": 19,
    "missing_question": 2,
    "missing_answer": 0
  }
}
```

### 3. 优化配对算法

当前配对逻辑：
- 简单基于题号匹配

未来可以优化：
- 考虑题号变体（如"22"和"22-续"）
- 考虑跨张题目
- 考虑手写题号识别错误
